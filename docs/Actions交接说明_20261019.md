## 2. 确认仓库设置（关键，缺一项必失败）

打开 `Settings → Actions → General`：

| 设置项 | 必须是 |
|---|---|
| Actions permissions | Allow all actions and reusable workflows |
| Workflow permissions | **Read and write permissions**（否则最后 `git push` 会 403） |
| Allow GitHub Actions to create and approve pull requests | 不用勾 |

打开 `Settings → Secrets and variables → Actions`：**本 workflow 不需要任何 secret**（代理在云端用不上，墙外直连）。

---

## 3. 手动触发一次

`Actions → daily-collect → Run workflow → 分支选 main → Run`

**预计耗时 15–25 分钟**（OECD 129 页约 2 分钟，gov.uk 9 组检索约 3 分钟，全文抓取约 10 分钟）。

### 每步预期输出

| 步骤 | 预期 | 失败怎么办 |
|---|---|---|
| 检出 main 分支 | success | — |
| 检出 data 分支 | success 或 warning | **首次运行 data 分支不存在 → 会 warning，这是正常的**，`continue-on-error: true` 已处理 |
| 安装 Python / 依赖 | success | 依赖已在 `requirements.txt`（feedparser/pandas/requests/PyYAML/beautifulsoup4/openpyxl） |
| 恢复主表 | 输出"data 分支无主表，将新建"或"已恢复 data 分支的主表" | — |
| RSS 增量 + 回填 | 各源 ✅，新增若干条 | 见下方排查表 |
| 回填 OECD 概述正文 | success（可能 0 条，正常——没有 SPA 记录就不用补） | 已 `continue-on-error` |
| 抓取新增记录全文 | 成功 N 条 | — |
| 采集六大巨头博客 | 6 家逐一 ✅ | NVIDIA 的 `blogs.nvidia.com` 偶发 TLS 重置，`continue-on-error` 已加 |
| 导出与报告 | 生成 `exports/` 下 6 个文件 | — |
| 提交到 data 分支 | `git commit` + `git push` | 见下 |

### 可能的失败与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| 最后一步 `git push` 报 403 | Workflow permissions 不是 "Read and write" | 回到第 2 步改设置，重跑 |
| `检出了 data 分支` 步骤失败但整个 run 继续 | 首次运行没有 data 分支 | 正常，忽略 |
| `fatal: could not read Username` | 同上，权限问题 | 同上 |
| OECD 步骤 ConnectTimeout | 云端网络瞬时问题 | 重跑；云端在墙外，理论上不会 |
| 报告步骤 `IllegalCharacterError` | 已修（exporter 有 `_xlsx_safe`） | 若仍出现，把报错贴我 |
| `blog` 步骤 OpenAI 大量 403 | Cloudflare 对云端 IP 限流 | 已 `continue-on-error`，不影响整体 |

## 4. 跑完之后验证

```bash
git fetch origin data
git checkout origin/data -- data/policy_master.csv data/runs.csv
python -c "import pandas as pd; d=pd.read_csv('data/runs.csv'); print(d.tail(5).to_string())"
```

**预期**：`runs.csv` 里出现一行 `command` 为 `update` / `backfill all` / `blog` 的记录，并且 `time` 是 UTC 时间（比北京时间晚 8 小时）。

这才是"云端真的跑过"的**唯一证据**——原报告里 `runs.csv` 只有 10-16 当天的 5 次本地运行，没有任何云端记录。

再确认数据分支有产物：

```bash
git ls-tree -r origin/data --name-only | grep -E "policy_master|signal_master|exports/"
```

**预期**：能看到 `data/policy_master.csv`、`data/signal_master.csv`、`exports/` 下的若干文件。

## 5. 跑通后要做的一件事

确认云端 cron 生效：`Actions → daily-collect` 页面顶部应显示
`This scheduled workflow is disabled because there hasn't been any repository activity for 90 days`
**这类提示只有长期无提交才会出现**；正常情况下每天北京时间 09:00（`0 1 * * *` UTC）自动跑一次。

若想立刻验证 cron，不用等：改一次 `workflow_dispatch` 手动触发即可。
